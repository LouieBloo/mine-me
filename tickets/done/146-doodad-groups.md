# 146 - Doodads that spawn in groups, clumps and meadows

**Priority:** P2 - **Status:** Done (closed by the owner 2026-10-27; doodads still need tuning) - **Depends on:** 100 (generation), 143, 145

## Problem
Every doodad is an independent random roll per cell, and `minSpacing` pushes same-kind doodads apart, so everything is thin and even. Mushrooms should usually be near each other, grass should come in big patches (and in grassy biomes, lots of it), and only bugs should be random.

## Decisions (2026-10-26, from the owner)
- **Per-doodad group settings, easy to configure in the admin**, and able to make big patches (like grass).
- **Grass: clumps that merge into meadows.** Large group sizes and spread let a biome's density decide between clumps and a full meadow.
- **Cap: raise it and count per kind.** The default `doodadMaxCount` goes up (about 1500) and each doodad may have its own limit, so grass cannot use the whole budget and starve rarer doodads. Check the cost in the F3 profiler.
- **Grassy biomes: all four that have grass** (default, clay pits, gravel banks, sandstone hollows), tuned by link density (assumed: default 3, clay pits 2.5, gravel banks 1.5, sandstone hollows 0.7), shallow only as now.

## Proposed design
- **Data (`DoodadSpawnRules`, stored in the existing `spawn` JSON, so no schema change):** `groupChance` (0-1: how many of its placements belong to a group; 0 = today's scatter, bugs), `groupSize` (min/max members), `groupSpread` (how far from the centre, in small blocks), `groupFill` (0-1 share of eligible spots inside the spread that get one; high = meadow), and `maxCount` (this kind's own limit). `minSpacing` then applies only between members of *different* groups (so groups do not overlap), and a small `memberSpacing` (default 0) inside one.
- **Generation:** the per-cell roll that exists becomes the roll for a group *centre* (probability scaled so a kind's overall amount still follows weight x density x base chance, divided by the expected group size). A centre that fits grows its group: candidate spots within `groupSpread` on the same surface (walk along the floor/ceiling/wall, not through air), each rolled against `groupFill`, each checked with the same footprint/support rules, a size picked per member. Group members may be fewer than asked when the surface runs out; a lone centre is a valid group of one. Still deterministic for a seed with the doodads' own random stream; a doodad with `groupChance` 0 draws no extra random numbers (existing maps unchanged).
- **Biome control:** the link's `density` raises the centre count and the fill, so a grassy biome gets more and denser meadows, and a poor one only a few clumps.
- **Cap:** groups are taken whole where possible; per-kind `maxCount` and the global cap are applied in the existing shuffled order. Raise `DEFAULT_DOODAD_MAX_COUNT` and the map config's default.
- **Admin:** a Groups panel on the doodad page (chance, size range, spread, fill, per-kind limit) with plain-language hints and a preview line; the sandbox generator toggle (107) shows the result; validation in `validateDoodad`.
- **First values (to tune in the game):** mushrooms (cave, glow): chance 0.8, size 3-8, spread 6; grass tuft: chance 1, size 10-40, spread 14, fill 0.7; wall moss: chance 0.7, size 3-10; stalagmite/stalactite: chance 0.5, size 2-5; glow crystal: 0.8, size 2-5; icicle: 0.6, size 3-8; beetle, firefly, dripping stalactite, lava vent: 0.

## Tests
Same seed, same placements; a doodad with groupChance 0 produces exactly today's placements (regression against current output); groups are contiguous on a surface and respect support, blocks, depth and biome; members never overlap; meadow fill covers most of a floor run; per-kind limit and the global cap hold; a kind with groups cannot starve another (per-kind limit); biome density changes the amount; admin validation; mutation: make groupFill ignored -> the meadow test fails.

## Built (2026-10-26)
- **Settings** (in the existing `spawn` JSON, no schema change; shared `DoodadSpawnRules` + `validateDoodadSpawnRules`): `groupChance` (0-1), `groupSizeMin/Max`, `groupSpread`, `groupFill` (0-1), `memberSpacing`, `maxCount` (this kind's own limit). Defaults once grouping is on: 3-8, spread 6, fill 0.5, gap 0. Pure helpers in `gameLogic/doodad/doodadGroups.ts` (`resolveDoodadGroups`, `splitGroupChance`, `groupFillChance`).
- **Generator** (`DoodadGenerator.ts`): a kind with no `groupChance` takes the original path with the same random numbers in the same order (a frozen copy of the old generator, `legacyDoodadGenerator.testutil.ts`, is compared against on several seeds and maps). A grouping kind makes one roll per cell: the low part is a lone doodad (`chance x (1 - groupChance)`), the next a group centre (`chance x groupChance / mean size`). A centre grows its group over free spots within `groupSpread` along the same surface (floor/ceiling: sideways, at most 3 rows across; wall: up and down, at most 3 columns across; air: every way), each rolled against the fill (full at the centre, half at the edge, times the square root of the biome density, never over 1), each placed with the usual footprint, support, block, depth, near-fluid and biome rules (a spot where the kind's biome mix is 0 is skipped). Groups are shuffled and taken as one unit, so the global cap and the kind's `maxCount` cut between groups where they can. `minSpacing` now only separates different groups and lone ones; `memberSpacing` separates members of one group.
- **Cap:** `DEFAULT_DOODAD_MAX_COUNT` is 1500; the schema default, the config service fallback and the admin hint follow.
- **Admin:** a Groups panel (`DoodadGroupsPanel`) on the doodad page: share in percent, size range, spread, fill, gap, per-kind limit, and a one-line summary. `tidySpawn` drops group settings without a share. The sandbox generator toggle runs the same generator, so it shows groups too.
- **Data script** `prisma/add-doodad-groups.ts` (dry run by default): the group settings from the ticket for mushrooms, grass, wall moss, stalagmite/stalactite, glow crystal and icicle (bugs, dripping stalactite and lava vent stay scattered), grass link densities, and the map config cap 400 -> 1500. It keeps settings an admin already made.
- **Tests:** shared helpers and validation; generator regression against the old algorithm, determinism, clustering vs scatter, amount near the scatter's, support/overlap on a lumpy cave, fill, meadow runs, biome density, minSpacing vs member spacing, per-kind limit, global cap, entrance and fluid; admin panel, summary and `tidySpawn`; script plans. Mutation-checked: ignoring the fill, an extra random draw on the old path, spacing applied inside a group, and ignoring the kind's limit each fail tests.

## Findings from real maps (dev DB definitions)
- Same-kind nearest-neighbour distance (blocks), three seeds, before -> after the new settings: glow mushroom 15/20/11 -> 1.9/4.4/2.3, glow crystal 13/21/12 -> 3.3/2.7/4.2, stalactite 7/7/10 -> 3.3/6.8/8.8, stalagmite 6/8/9 -> 4.2/3.4/3.7, icicle 5/3/6 -> mixed, grass 1-4 per map -> 6-28 per map in clumps. Bugs unchanged. Map build time stayed about 190-300 ms.
- **Grass is limited by where the cave is, not by the settings:** only about 30-70 open floor cells exist in the grass window (rows 1-45) in a whole map, and the surface itself (above the ground) gets no doodads until ticket 135. Even with every spot taken that is a few small meadows, so the grass window (`maxDepth` 45) should be widened in the admin (for example to 90) to get large meadows.
- A group's chance is divided by its size, so a kind with few eligible spots (wall moss, grass) varies a lot from map to map: some maps get no group. Raise the link density to make groups reliable, as done for grass (densities 120 / 120 / 50 / 12 because the seed's scale is already about 7 for "1x").
- Wall and ceiling groups come out smaller than their size range because short walls run out; lower their sizes or raise their density if clumps look thin.
