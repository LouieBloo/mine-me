# 120 - Extractor entity, landing intro and placement

**Priority:** P1 - **Status:** Done in code (judge the look in the game) - **Depends on:** 119, 139 (sky rows)

## Decisions (2026-10-22, from the owner)
- On game start the extractor **flies in and lands on the surface**.
- **It is not on the entrance/exit; it sits offset from it.** The entrance stays the exit.
- **One shared extractor and belt per run**, used by all players.

## Proposed design
- Server: a `MiningExtractor` entity created at session start at an x offset from `ENTRANCE_X` (offset in data, default a few blocks to the side, on flat ground; the generator guarantees a flat landing pad clear of rocks, doodads and the entrance zone).
- Landing is a client animation driven by a start timestamp so late joiners see it already landed (no replays). Pixi renders the extractor and landing (animation, dust particles, landing sound through the sound library). The extractor is a world graphic; any UI stays DOM.
- The shaft start cell sits under it. Until it has landed the belt does not build and deposits are disabled.
- Collision: the extractor is a platform/solid for the player? (Decision: the player can walk onto it; it has a deposit zone, see 121.)
- Wire: static description once; state (landed, belt length) as small deltas.

Placement offset and flat pad guarantee, late join sees it landed, no belt build before landing, deterministic per seed.

## Progress (2026-10-22)
- `Extractor` gained `entranceOffset` (cells from the exit to the machine's middle, default 24) and `landingSeconds` (default 3). `placeExtractor` (shared, pure) puts it on the ground at `surfaceRow`, keeps it clear of the exit (min distance = half its width + 1 block) and inside the map. The surface row is plain level dirt by construction, so no extra pad guarantee was needed.
- `MiningExtractorSubsystem` (server): placement, landing clock on the sim clock started by the first player to join, `isLanded()` (the belt 122 and the deposit zone 121 check it), `landed` sent once in the tick (`extractor: { landed: true }`), description sent once in the join state (`extractor` with `landingRemaining`, so a late joiner sees it already down). Not in the sandbox (`hasExtractor` in the game mode rules; 127 adds it).
- Client: `ExtractorRenderer` (Pixi) draws a placeholder (or the art once `textureUrl` is set), flies in on an ease, kicks up the landing particle effect and plays the landing sound at its own volume, via the scene, ticker and tick handler.
- **Deviation:** the player does not stand ON top of the machine (a jump over 9 cells is out of reach, and a one-way platform would need new shared physics for client prediction). The machine is not solid; the deposit zone (121) is its footprint at ground level, so "walk onto it" works.
- The drawn landing starts when the client builds the scene and can end slightly after the server says `landed`; gameplay uses the server's flag.
