# 120 - Extractor entity, landing intro and placement

**Priority:** P1 - **Status:** Open - **Depends on:** 119, 139 (sky rows)

## Decisions (2026-10-22, from the owner)
- On game start the extractor **flies in and lands on the surface**.
- **It is not on the entrance/exit; it sits offset from it.** The entrance stays the exit.
- **One shared extractor and belt per run**, used by all players.

## Proposed design
- Server: a `MiningExtractor` entity created at session start at an x offset from `ENTRANCE_X` (offset in data, default a few blocks to the side, on flat ground; the generator guarantees a flat landing pad clear of rocks, doodads and the entrance zone).
- Landing is a client animation driven by a start timestamp so late joiners see it already landed (no replays). Pixi renders the extractor and landing (animation, dust particles, landing sound through the sound library). The extractor is a world graphic; any UI stays DOM.
- The shaft start cell sits under it. Until it has landed the belt does not build and deposits are disabled.
- Collision: the extractor is a platform/solid for the player? (Decision: the player can walk onto it; it has a deposit zone, see 121.)
- Wire: static description once; state (landed, belt length) as small deltas.
